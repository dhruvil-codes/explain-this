Kubernetes is a system for running software packaged in containers across many machines. Instead of logging into servers and starting programs by hand, you describe the result you want, and Kubernetes works continuously to make it real and keep it that way.

You state your wishes in small files that declare a desired state: which container image to run, how many copies you want, which network ports to open, and how much memory each copy may use. The command-line tool kubectl sends these wishes to the cluster's front door, a component called the API server. Every change, whether from you or from the system itself, goes through this server, which checks that it is valid and permitted.

The brain of the cluster is the control plane. It stores the whole desired state in etcd, a small but extremely reliable database built for agreement across machines, so the plan survives even if parts of the system fail. The scheduler watches for work that has no machine yet and assigns each unit to a suitable node, weighing available CPU and memory along with rules you set, such as keeping copies on different machines. Controllers run as endless control loops: each one compares what it sees with what was asked for and takes action to close the gap, for example starting a replacement copy when one crashes.

The machines that do the actual work are called nodes, and each one runs an agent named the kubelet. The kubelet receives its assignments from the API server, starts the containers, restarts them if they fail health checks, and reports status back. A network helper called kube-proxy routes traffic to the right copies. The smallest unit Kubernetes manages is the pod, usually one container plus its settings, and pods are grouped into Deployments that keep the requested number of copies alive through updates. A Service then gives the whole shifting set of copies one stable address, so your users never need to know which machine answered them.
